## 2. 关键结论（三句话）

1. **数据集是完整的。** 云端 `eegmat` 有 **72 个 EDF = 36 被试 × 2 段**，无缺号、无子目录、**无第三段**。
2. **本地副本确实残缺。** 本地只有 2 个被试，属「只下载了样本」，与数据集本身无关，可重下修复。

## 4. 决定性对账：处理产物来源已验证为真

用**本地 4 个文件**实测的窗数（静息 182 s → 91 窗，心算 62 s → 31 窗，每人 122 窗），
去反推 36 人总量，再与云端 metadata 对照：

| 对账式 | 计算值 | 云端实测 | 结果 |
|---|---|---|---|
| `25 × 91 + (40 + 85 + 94)` = 静息窗 | 2494 | 2494 | ✅ |
| `28 × 31` = 心算窗 | 868 | 868 | ✅ |
| 合计 = train | 3362 | 3362 | ✅ |
| `4 × 91` = val/test 静息 | 364 | 364 | ✅ |
| `4 × 31` = val/test 心算 | 124 | 124 | ✅ |
| `3362×8×500×8 + 128 B` | 107584128 | 107584128 | ✅ |
| `488×8×500×8 + 128 B` | 15616128 | 15616128 | ✅ |

> **其中 `40 / 85 / 94` 三个异常值，是本地独立预测、云端独立实测，两边完全一致。**

**→ 结论：`data/processed/mental_arithmetic_250hz_8ch` 确实是真实 36 人数据，
不是从本地 2 人复制/伪造的。此前所有训练与评估跑的是真数据，可继续引用。**

**次要发现**：数组 dtype 是 `float64`（非 float32），内存占用翻倍
（train 107 MB vs 53 MB）。训练时可 `.astype(np.float32)` 省一半内存与带宽。
